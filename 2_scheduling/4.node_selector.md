### Node Selector
- A way to schedule pods on specific nodes [Specific node is identified on the bases of labels]
- So, there are two steps.
  - 1. Adding label on the node `kubectl label nodes nodename key=value`
  - 2. Adding a section in pod specification 
    ` nodeSelector:
        key: value
    `

But node selector have limitations, 
- We cannot say something like place the pod on the node which is not large or which is either small or medium.

To overcome this limitation, we have Node Affinity

affinity:
    nodeAffinity: 
        requiredDuringScheduleIgnoreDuringExecution:    
            nodeSelectorTerms:
                - matchExpressions:
                    - key: size
                      operator: In


Two stages of the Pod
- During Schedule, it is a stage where pod is being created for the first time [required | preferred]. required means that a matching rule must exist, 
otherwise the pod will not be sceduled. preferred means, if exist, schedule there else schedule any where
- During Execution, when the pod are scheduled and running and someone delete the labels, there will be no impact if we set IgnoreDuringExecution. 

- requiredDuringScheduleIgnoreDuringExecution: It means that during scheduling, when the pod is being scheduled, there should be a matching rule.
