Request -> Authentication via Certificates stored in ~/.kube/config file. Then
authorization happens to check if it has access to access the resource which is 
configured via rbac.

Now, these two steps [authentication and authorization] are to validate the access but
what if you want to apply rules at the configuration level, like 
- manifest file must have labels
- image key should not have an image with latest tag

Then, we can use admissionControllers. 

when we do kubectl apply -f pod.yaml

Request -> Authentication -> Authorization -> Admission Controllers -> Create Pod

Some admission controllers are 
- alwayspullimages
- defaultStorageClass
- EventRateLimit
- NamespaceExist


command
```kubectl exec kube-apiserver-minikube -n kube-system -- kube-apiserver -h | grep enable-admission-plugins```

Types of AdmissionControllers
- Vallidating admission controllers - which will just check if something is true or not [namespace exist or not]
- Mutating Admission Controllers - will add information in the manifest file, if we are making a pvc, and haven't specified the storageClass, defautl will be added the pod.yaml file


First, mutating admission controllers are applied, then validating. So, changes made can be validated as well.


We can make custom admissionControllers

- make a webhook which accept request and do response in certain format
- deploy it or run as a pod
- Then, make an object with the type ValidatingWebhookConfiguration or Mutating
