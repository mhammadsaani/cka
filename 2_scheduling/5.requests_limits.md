- Kube Scheduler takes into accounts the amount of memory and cpu required for pod and 
decide the node for the pod accordingly.

- If there are not avaiable resources, the pod will be in the pending state as there are not sufficient ressources.

Resource Request is the min amount of the resources (memory and cpu) required by pod. 
Resource Limits are the max amount that the pod can request

resources:
    requests:
        memory: "4Gi"
        cpu: 2
    limits:
        memory: "6Gi"
        cpu: 4


1 count in CPU is equal to 1 virtual CPU in aws, 1 core in azure and gcp.
Memory is either in Gi or G, where Gi refers to Gibibyes 1Gi = 1GB = 1024MBs
1G is 1 gigabyes which is 1G = 1000MBs


A pod cannot access more cpus than defined in the limits, cpu will be throttled. 
However, in case of memory, a pod can use the memory more than limit, but if 
pod is consuming memory constantly, it will be OOM (Out of memory) error.


K8s doesn't set requests limits by default, we have to define them in the pod or better we can 
define at namespace level using kind: LimitRange

apiVersion: v1
kind: LimitRange
metadata:
  name: cpu-resource-constraint
  namespace: prometheus
spec:
  limits:
  - default: # this section defines default limits
      cpu: 500m
    defaultRequest: # this section defines default requests
      cpu: 500m
    max: # max and min define the limit range
      cpu: "1"
    min:
      cpu: 100m
    type: Container


We can also restrict the quotas at the namespace level that all the pods 
in the given namespace shouldn't consume more than the giving request limits 
using k8s object called ResourceQuota
