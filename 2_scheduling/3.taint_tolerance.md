### Taint [To contaminate something]

Lets say, we contaminated something, now there are certain this which can tolerate the contaiminated things but not all. The same idea is behind
taint and tolerantion in k8s.

We taint the nodes, meaning only few pods which can tolerate the contaiminated nodes can be scheduled on that node.
So, we can see taints are applied on nodes and toleration on pods

`kubectl taint node node-name key=value:effect`


- Effect, what happens to the pods that do not tolerate the taint. 
 - NoSchedule: Pods will be not scheduled on the nodes
 - PreferNotSchedule: System will try not to place the pod on this node
 - NoExecute: Existing pods will be evicting if they exist and do not tolerate the taint, new pods will only schedule if they meet the criteria

- Scenario:
 If there is taint only on first node, and we have 3 nodes. There is a posibility that our pod which have toleration for the taint on node 1, might be 
 scheduled on the other nodes as they don't have any taint. So, what to do in this scenario? 
 - Apply different taints on all the nodes
 - Use concept of affinity

- No Pod is scheduled on Master node
  Reason: As taint is applied on the master node, when cluster is created, no pod is scheduled there which is a good practice. 
  `kubectl describe node kubemaster | grep Taint`
